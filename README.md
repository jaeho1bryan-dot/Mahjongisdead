# 청록장 · Mahjong is dead

TypeScript 기반 4인 웹 리치마작입니다. 한국어 React UI, 직접 제작한 SVG/CSS 입체 패, 실시간 친구 대국과 빈자리를 채우는 연습 봇을 제공합니다. 작혼·마작일번가의 이미지나 음원을 사용하지 않습니다.

## 실행

Node.js **22.12 이상**이 필요합니다.

```sh
npm ci
```

개발할 때는 터미널 두 개에서 실행합니다.

```sh
npm run dev:server
```

```sh
npm run dev
```

브라우저에서 `http://localhost:5173`에 접속합니다. 닉네임과 대국 방식을 선택해 방을 만들고, 초대 링크 또는 방 코드를 공유하세요. 방장이 시작하면 빈자리에 봇이 들어갑니다. 혼자 시작해도 됩니다. 첫 친(오야)은 방장과 관계없이 무작위로 정해지며, 국 시작 알림에 표시됩니다.

빌드한 앱과 게임 서버를 한 포트에서 실행하려면:

```sh
npm run build
NODE_ENV=production npm start
```

`http://localhost:3001`에서 접속합니다. `npm run preview`는 프런트엔드 미리보기일 뿐 게임 서버를 연결하지 않으므로, 실제 대국 검증에는 위 명령을 사용하세요.

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | `3001` | Node HTTP/WebSocket 포트 |
| `HOST` | `0.0.0.0` | 수신 인터페이스 |
| `NODE_ENV` | 미지정 | 배포 시 `production` 지정 |
| `WS_ALLOWED_ORIGINS` | 없음 | 추가로 허용할 웹 Origin의 쉼표 구분 목록 |
| `DEV_PORT` | `5173` | 개발 모드에서 허용하는 동일 호스트 프런트엔드 포트 |

Vite는 `/ws`와 `/health`를 기본 서버 포트 3001로 프록시합니다. 개발 서버 포트를 바꾸면 `vite.config.ts`의 대상 포트도 변경해야 합니다. 외부 서비스에는 HTTPS와 WebSocket 업그레이드를 지원하는 리버스 프록시를 사용하고, 원래 `Host` 헤더를 보존하거나 `WS_ALLOWED_ORIGINS`를 정확히 지정하세요. Origin 검사는 사용자 인증을 대신하지 않습니다.

## 플레이

- **버리기:** 내 차례에 활성화된 패를 클릭합니다. 마지막으로 뽑은 패는 손패와 떨어져 표시됩니다.
- **리치:** 리치 버튼을 선택하고, 표시된 합법적인 리치 선언패를 버립니다.
- **울기 / 화료:** 치·퐁·깡·론·쯔모 중 가능한 행동만 나타납니다. 여러 조합은 각각 버튼으로 표시됩니다.
- **국 결과:** 역, 부·판수, 점수 이동, 화료패와 우라도라 표시패를 확인합니다. 역 이름과 판수는 한국어로 표시합니다(예: 리치, 탕야오, 역만). 모두 확인하거나 제한 시간이 지나면 다음 국으로 진행합니다.
- **시간 제한:** 기본 20초입니다. 응답이 없으면 자동 진행합니다.
- **재접속:** 같은 탭에서 새로고침하면 `sessionStorage`의 자리 토큰으로 복구합니다. 연결이 끊긴 자리는 유예 시간 후 봇이 진행하며, 복귀하면 다시 조작할 수 있습니다.
- **나가기:** 진행 중 나가면 봇이 자리를 이어받고 해당 자리의 재접속 토큰은 폐기됩니다.
- **소리 / 도움말:** 상단에서 선택적인 행동 효과음과 규칙 가이드를 열 수 있습니다. 작은 화면에서는 손패 영역을 가로로 스크롤할 수 있습니다.

## 기술 선택과 규칙

요청에 제시된 [`takayama-lily/riichi`](https://github.com/takayama-lily/riichi)는 손패·점수 계산 라이브러리입니다. 전체 대국의 상태 전이, 후리텐, 울기 우선순위, 연짱 등을 별도로 재구현하지 않도록 **[`@kobalab/majiang-core@1.4.1`](https://github.com/kobalab/majiang-core)**의 `Game`과 `Player`를 서버에서 사용합니다. MIT 라이선스 고지는 `THIRD_PARTY_NOTICES.txt`에 있습니다.

- **React + SVG/CSS:** 패 선택, 결과창, 반응형 테이블을 표현합니다. 고정된 보드 게임이라 Phaser/실제 3D 엔진은 추가하지 않았습니다.
- **Node.js + ws:** 이미 규칙 엔진이 상태 머신을 소유하므로 Colyseus 없이 방·접속·타이머를 얇은 계층으로 구현합니다.
- **서버 권한:** 클라이언트는 현재 프롬프트 ID와 서버가 제시한 행동 ID만 제출합니다. 점수, 패산, 손패, 역, 리치 여부를 클라이언트가 정하지 않습니다.
- **정보 분리:** 플레이어별 `Board`로 뷰를 생성하며 타인의 비공개 손패나 패산을 전송하지 않습니다. 화료 때 공개되는 손패는 결과 데이터에 포함됩니다.
- **패산:** Node `crypto.randomInt`로 Fisher–Yates 셔플을 적용하고 도라·우라도라 표시패를 다시 연결합니다. 영상패·왕패 처리는 엔진에 맡깁니다. 딜러 선택도 암호학적 난수를 사용합니다.

| 깡 | 암깡·가깡·대명깡, 영상패·깡도라·창깡, 국사무쌍의 암깡 창깡 |

| 유국 | 패산 소진·노텐 벌부, 구종구패·사풍연타·사가리치·사깡산료 등 엔진 기본 규칙 |
| 유국 만관 | 나가시만관 있음 |
| 연짱 / 종료 | 텐파이 연짱, 들통 종료, 오라스 종료·연장전은 엔진 기본값 |
| 역만 | 복합·더블·헤아림 역만, 책임지불 지원 |

한 국 연습도 연짱이 발생하면 여러 국이 이어질 수 있습니다. 이 룰은 두 상용 게임의 모든 모드와 동일하다는 의미가 아닙니다. 국사무쌍 텐파이는 다른 사람의 암깡 패로 론할 수 있으며(새 깡도라는 열리지 않음), 이를 넘기면 동순 후리텐이 됩니다. 엔진은 이 예외를 지원하지 않으므로 `server/room.ts`와 `server/player.ts`에서 보완합니다. 엔진의 모든 설정은 `node_modules/@kobalab/majiang-core/lib/rule.js`, 선택한 대국 설정은 `server/room.ts`에서 확인할 수 있습니다.

## 검증과 구조

```sh

npm run lint

```

Node 내장 테스트 러너와 `tsx`로 규칙 픽스처 및 실제 WebSocket 통신을 검증합니다. 패 구성·점수·역 없음·후리텐·리치·치 방향·쿠이카에·깡·유국·완주, 정보 분리·재접속·잘못된 행동 거부, 패의 접근성 이름·렌더링 등을 검사합니다. 테스트는 표본 기반의 회귀 검증이며 모든 가능한 패 조합이나 두 상용 서비스와의 완전한 일치 증명은 아닙니다.

```text

server/room.ts       방, 자리, 프롬프트, 타이머, 개인별 상태

src/Tile.tsx        원본 SVG 패 그림과 입체 표현
src/useGame.ts      통신, 재접속, 탭별 세션 보관
tests/             규칙 / 서버 / 표시 회귀 테스트
```

## 운영 범위와 제한

실제로 대국할 수 있는 **단일 프로세스 게임 구현**이지, 상용 서비스 전체를 복제한 것은 아닙니다.

- 방과 대국은 메모리에만 저장되어 **서버 재시작 시 소실**됩니다. 계정·랭킹 DB·기보 저장/재생·관전·매칭·채팅·과금은 포함하지 않습니다.
- 봇은 자기 손패와 공개 정보의 샹텐·유효패를 이용하는 연습 상대입니다. 사람 수준의 수비·전략 AI는 아닙니다.
- 기본 한도는 방 64개, 연결 256개, 직접 연결 IP당 32개, 메시지 4 KiB, 연결당 10초에 60개입니다. 무인/대기 방은 기본 15분, 방의 최대 수명은 6시간이며 주기적으로 정리됩니다. 세부 값은 `createServer` 옵션에 있습니다.
- 프록시 뒤에서는 직접 연결 IP가 프록시 IP가 될 수 있습니다. 규모가 있는 배포에는 신뢰 프록시 정책, 외부 접속 제한, 부하 시험과 적절한 서버 옵션 구성이 필요합니다.
- 방 코드는 초대 편의 기능이며 계정 기반 접근 제어가 아닙니다. 자리 토큰은 비밀번호처럼 취급하고 공유하지 마세요.
- TLS 종료, 영속 저장, 수평 확장, 운영 모니터링, 대규모 부정행위 방지는 별도 운영 작업입니다.
